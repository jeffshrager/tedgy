## What we discussed

### The concept: "TedGy" (working name)
A "Paper AI" system for managing a multi-week middle school (8th grade) project run by a lead teacher named Ted. Multiple student teams do roughly the same project but can diverge based on their progress.

### Daily cycle
1. Ted provides an initial project spec + day-by-day plan at project start
2. Each morning: software generates a per-team PDF (printed, handed to students)
3. Students physically annotate it throughout the day (done / blocked / ahead / names / filled-in graphics)
4. Each evening: operator ("The Wizard") uploads annotated scans + Ted's next-day plan + an "OzNote"
5. Software generates tomorrow's per-team PDFs, adapted to each team's diverged state

### Key architectural insight
Each team has an **independent, persistent Claude conversation** that accumulates context. Teams that are behind get different guidance than teams that are ahead, even though the underlying project is the same.

### The OzNote
A meta-prompt from the operators (the Wizard) that shapes how Claude interprets the day's inputs and crafts tomorrow's sheets. Does not appear on the printed page — it's a behind-the-scenes steering wheel.

### Input format decision: Grayscale scan
- Pencil on white paper → grayscale is ideal, no info lost vs. color
- Smaller files, easier pipeline
- Claude Vision reads handwritten names, checkboxes, and filled-in diagrams well at this fidelity
- Recommended 200-300 DPI
- Consistent orientation matters (document feeder > phone photos)
- Wizard will handle occasional mis-reads manually — no need to over-engineer OCR correction

### Forms design note
Printed forms should constrain student input: labeled blanks, fixed-structure diagrams with specific fill-in slots rather than free-draw, to make vision parsing more reliable.

## Decisions made this session
- **Scan input: flatbed/document-feeder scanner** (not phone photos). Clean, consistent orientation, reliable quality.
- **Ted's input format: PowerPoint** — extract text/structure with python-pptx; Ted doesn't need to change his workflow.
- **Daily output format: Markdown → PDF via Pandoc** — single template, consistent look. Contents per sheet:
  - Header block (team name, day, phase, progress)
  - "Where we are / where we're going" narrative (Claude writes per-team)
  - Kid-friendly Gantt chart (table or ASCII bars: weeks × tasks, shaded by status)
  - Today's task checklist (physical tick boxes)
  - Fill-in sections (role assignments, labeled blanks, structured diagrams)

## Evening workflow (multi-stage, iterative)
1. **Ingest**: Op drops scans into `days/N/<team>/scan.png`
2. **Summarize**: TedGy reads scans + team contexts → writes `days/N/summary.md` (progress, issues flagged)
3. **Oz reviews** summary → writes/edits `days/N+1/oznote.md`
4. **Generate**: TedGy reads plan + OzNote + team contexts → writes `days/N+1/<team>/sheet.pdf`
5. **Oz reviews PDFs** → if off, edits OzNote and re-runs step 4 (idempotent overwrite). Loop until done.

**OzNotes are global (one per day, not per team).** Oz can address specific teams in plain text ("make sure team Alpha is reminded to...") and Claude applies it selectively per team during generation.
